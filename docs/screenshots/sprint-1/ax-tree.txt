Accessibility tree of Shelf, sidebar and inspector — Sprint 1 evidence
=====================================================================

Taken from the running Release build with the 5 000-book measuring library
open, window 1440 x 881, one book selected. Read with the AX API (the same
tree VoiceOver walks), not from a screenshot. Abridged: the tag, author and
series lists are cut after a few rows, and the cover grid is left out.

What it shows, and what it shows is missing:

* Every sidebar section is present and filled, and the empty ones say why
  ("Shelves arrive in Sprint 2", "Devices arrive in Sprint 5").
* A sidebar row is an AXImage plus two AXStaticText elements, with the help
  text repeated on each. It has no AXButton role and no action, so a
  VoiceOver or keyboard-only user cannot activate it. Sprint 7 (accessibility)
  has to give these rows a role.
* The counts read "4.996" — grouped in the user's locale — while the status
  bar one line below reads "4996 books". Two number formats in one window.
* The rating control comes out as AXUnknown with a description and, as first
  written here, "no value". **That was wrong**, and the fault was in the tool:
  SwiftUI puts `.accessibilityValue` on a custom control into
  `AXValueDescription`, and the first version of the dumper read only `AXValue`.
  `Scripts/ax-dump.swift` reads both now. See ../sprint-2a/ax-tree.txt.
