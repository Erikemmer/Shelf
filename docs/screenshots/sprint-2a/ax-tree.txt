Accessibility tree of the inspector after Sprint 2a — the editable fields
=========================================================================

Taken with `swift Scripts/ax-dump.swift <pid>` from the running Release build,
one book selected, rating set to three stars with the keyboard (the 3 key) and
the read status left off. Read-only; this is the tree VoiceOver walks.

What it shows:

* The star control publishes its value: `valueDescription="3 of 5"`. The OPF
  beside the book says `calibre:rating` 6 at the same moment, which is the
  same rating on Calibre's ten-point scale.
* The read status is an `AXCheckBox` with a value, where Sprint 1 had a static
  "Read: No" text. A keyboard-only user can reach and toggle it.
* Both carry help text naming their keys.

Note on the Sprint 1 excerpt in ../sprint-1/ax-tree.txt: it claimed the star
count was "not readable by assistive technology". That was wrong, and the fault
was in the tool, not the app – SwiftUI puts `.accessibilityValue` on a custom
control into `AXValueDescription`, and the first version of the dumper only
read `AXValue`. `Scripts/ax-dump.swift` reads both now.
